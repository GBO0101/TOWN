# AI 辦公室架構與驗證

目標：把角色決策、每日結算、事件與啟動控制集中到各自負責的檔案，讓主迴圈只保留執行順序。

## 已確認的行為

- 工作任務回自己的座位，抵達後才開始計時。
- 咖啡、廁所、會議與業務外勤可以離席。
- 午餐時段可以工作，效率為正常的 75%；跨時段任務依實際工作時間加權。
- 公司支出先列應付，每日 20:30 換日前一次支付到期款項；訂金及到期尾款即時收現，收入依交付認列。
- 沿用原生 JavaScript 與 script 載入方式，不新增框架、套件或建置步驟。
- 擴張及聘任由老闆自動決定；座位依需求動態增加，沒有固定等級。
- 專案工作持續入帳，保留中斷前的工時；依職能與現有人力分案，顯示各案工作量及目前工作人數。
- 人物任務完成前保持穩定，午餐每日只選一次；加班依實際政策與意願執行，外勤返座後才可再次派遣，已下班不召回。
- 員工按實際有效工時累積經驗，次一營業日依職等自動晉升調薪；薪資與人事附加成本接回既有財務流程。
- 健康影響實際產出與預估產能；實際加班增加消耗，減少加班及帶薪休養可恢復，低健康員工不被派回工作。最新規則與驗證見 [健康與恢復](employee-health.md)，證據位於 `.scratch/employee-health/`。
- 自研產品上線從零付費客戶開始，由業務實際獲客；收入與伺服器、機房等用量成本隨客戶數變動。規則與驗證見 [自研產品](passive-products.md)，證據位於 `.scratch/product-customers/`。
- 自研啟動定位於中後期：網站 300 萬、最早第 88 日；遊戲 800 萬、最早第 176 日，投入外另留三個月營運準備，證據位於 `.scratch/product-investment/`。
- 上線產品隨機產生無報酬維護案，優先座位派工，逾期於日結流失客戶且仍可修復；停運取消其維護。生命週期與流失集中在 `passive-products.js`，證據位於 `.scratch/product-maintenance/`。

## 視覺規則

`style.css` 是樣式入口，依序載入以下五層：

| 檔案 | 責任 |
|---|---|
| `styles/tokens.css` | 色彩、間距、字型、共用按鈕及四種頭像尺寸 |
| `styles/layout.css` | 標題列、頁面區域、面板外框與響應版面 |
| `styles/office.css` | 房間與家具外觀、人物、說話與任務進度 |
| `styles/panels.css` | 日誌、人物標籤與角色卡 |
| `styles/overlays.css` | 角色詳情、記憶、遲到記錄與通知 |

- 沿用既有 SVG；新增未知訪客的備用圖形。歷史人物透過角色資料查頭像，避免直接用 ID 拼出不存在的圖檔。
- 人物與角色卡依身分重用 DOM；離開的訪客及離職人物從場景移除。
- 日誌資料換成新陣列時重建快取，避免重置後相同事件 ID 留下舊內容。
- 工作區在平面圖中央；其他房間縮放到上方與兩側。房間和家具位置由 OfficeLayout 統一設定。
- 工作區按座位數增加列數，場景高度同步延伸；周邊房間維持獨立高度。家具、桌牌、聘任及互動共用 CompanyGrowth.desks，新增座位可即時操作。
- 右側公司成長、專案進度及日誌各有縮小／展開按鈕，自研使用原生 details；只隱藏內容，保留標題與摘要。PanelView.init 在啟動時註冊一次控制，重置模擬保留同頁收合狀態，日誌保留閱讀位置或繼續跟隨最新事件。
- 模擬座標保持獨立，人物沿顯示路徑移動，不更動實際任務的抵達時間。
- 窄螢幕依容器寬度調整平面圖，完整呈現中央工作區；兩側房間仍可橫向捲動操作。
- 四周留安全邊距，縮放視窗及重置時重新置中；狀態與事件提示固定在場景外層，桌面角色詳情位於日誌區。
- 角色詳情可進入完整記憶與關係；Esc 關閉面板後還原焦點。

## 午餐與公司結算

- 午餐時段沿用 11:30–13:00。角色可依工作意願選擇工作，吃飯與外出的選擇仍保留。
- 工作任務記錄抵達後的開始時間；只有落在午餐時段的工作時間套用 75% 效率。
- 公司所有支出呼叫 CompanyFinance.charge 累計，只有 CompanyFinance.settle 會扣款。
- 月薪與營運成本按日提列、每 22 個營業日到期；資金判斷扣除全部已提列應付。貸款以未還本金計息，還本金不計費用。
- 20:30 換日前支付到期帳款，記錄分類明細；未到期及無錢支付的餘額保留。個人存款依實領金額增加，重置清空完整財務狀態。
- 訂金、交付收入、尾款、損益與信用額度的詳細規則見 [小型接案公司經濟模型](economy-model.md)。
- 擴張、招募及新增空間成本的規則見 [公司動態擴張與員工聘任](company-growth.md)。
- 工時、多人分案、中斷與各案進度顯示見 [工作進度與人力分配](work-progress.md)。
- 人物排程、出勤、加班及狀態一致性見 [人物狀態與動作規則](character-rules.md)。
- 派工、含風險成本的估價及接案產能見 [接案產能、報價與利潤](project-profit.md)；自研上線及每日基礎設施成本見 [自研產品與被動收入](passive-products.md)。

## 測試與比較方式

- 測試透過 `test/office-scripts.js` 依 `index.html` 的順序載入正式腳本。
- 回歸測試涵蓋座位、抵達計時、外勤與會議例外、打卡、薪資、借貸、換日、重置及顯示。
- 在座位修正完成後建立重構基準，以種子 42、7 各連續模擬 31 天，比較完整模擬狀態的每日 SHA-256；工作區置中的顯示調整也先通過這 62 個比對。
- 午餐、結算、經濟模型及動態擴張是後續已確認的行為變更，不再以舊狀態雜湊判定正確性，也不覆寫舊基準。現行驗證包含正常營運兩組、零接案一組及大量工作一組，各 120 個營業日，檢查帳務、人物、座位及專案狀態。
- 基準與重現工具放在 `.scratch/ai-office-refactor/`；根目錄沒有 Git，所以使用本次內容備份與行為比較。


目前結果：10 個檔案、213 項測試、26 支前端腳本及 server.js 語法、70 個靜態 ID 通過。前輪四種子各 120 日接案與財務驗證無案件逾期；自研客戶模型完成過兩組正常公司各 264 日、一組資金充裕公司 180 日及零接案 120 日驗證。提高初始投入後，再以兩組正常公司各 440 日、資金充裕公司 352 日及零接案 120 日重驗，均通過帳務、非負現金與每日唯一付款；正常及充裕公司均在對應階段開發兩類產品並取得客戶。
