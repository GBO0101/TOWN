# 人物狀態與動作規則

本輪已確認重訂人物行為，保留公司經濟、動態擴張、聘任及專案系統。不是清空遊戲資料。

## 排程

`CharacterRules` 集中判定下一步與語意狀態；`scheduleNext` 保留為既有呼叫入口。`CharacterSimulation` 處理移動、抵達、工作累積及完成效果，職業動作由 `assignDeskTask` 回到自己的座位。

1. 離職、健康休養及當日已下班者停止工作排程；健康休養保留薪資及座位，不打卡或列遲到。
2. 進行中的任務保持到完成；會議、故障等事件仍可中斷並保留既有工時。
3. 員工 08:00 進門打卡後入座；首日老闆 07:30 可先到。外勤返回不重複打卡。
4. 11:30–13:00 每日選擇一次工作或午餐；吃完可恢復工作。午餐時段工作的有效工時為 75%，依時間加權。
5. 休息有間隔，伸展 0.1 小時，其餘 0.2 小時；移動完成才開始計時。休息／午餐完成後，下次休息間隔依特質為 1.5–2.5 小時。
6. 一般工作每段至多半小時，含座位職業動作。需先抵達自己的位置才累積工時，最晚工作時間不因移動而延長。
7. 17:30 後，有專案、心情至少 40%、健康至少 70%、工作意願至少 65% 才考慮加班；嚴格政策不安排，正常最晚 18:30，彈性最晚 19:30。無專案或健康不足即離開。
8. 走到大門才打下班卡；離職與換日有補登，避免遺漏應付加班費。現有月度到期與每日單次付款流程不變。

## 外勤

- 業務拜訪只由接案系統派遣，需在自己的座位且沒有受保護的移動、午餐、休息或會議；派遣窗口為 08:30–14:00。
- 經大門外出，拜訪最多 3 小時，最晚 17:30 結束。若需多次拜訪，中間先返回公司座位。
- 未完成接洽可保留隔日，已下班的人不被召回，人物動作不跨夜。
- 第 2 日起，老闆無進行中專案時可在 09:00–14:00 安排每日一次 1.5 小時洽談；合約仍使用既有建立入口。
- 外出午餐沿用相同移動與返回流程，最晚 13:00 結束外出用餐後返回。

## 狀態與顯示

物理狀態維持 `sitting`、`walking`、`standing`、`gone`；顯示狀態依出勤、位置及任務推導，避免新增互相矛盾的旗標。

| 情境 | 顯示 |
|---|---|
| 正在進門／回公司 | 到班入座／返回座位 |
| 回自己的座位途中 | 返回座位，尚不列入工作人數 |
| 在座位執行有效工作 | 專案工作／內部作業 |
| 休息、午餐、會議 | 對應活動與任務文字 |
| 外勤 | 業務外勤，保留大門外剪影 |
| 走向下班大門 | 前往下班 |
| 當日已離開 | 已下班 |
| 帶薪健康休養 | 健康休假；不顯示在辦公室中，保留人物卡與職位 |
| 離職或退休 | 已離職／已退休 |

場景、桌牌、人物卡及詳情共用 `CharacterRules.status` 與 `OfficeArt.activity`。健康來自 `sim.health`，不再以心情百分比代替；離職者顯示最後紀錄，缺資料顯示未記錄。離職者不再收到生活、心情衰減及團隊事件效果。

健康現在乘入專案效率、派工及預估產能；換日按實際工作與加班計算消耗，正常休息恢復。每日健康低於 40% 自動帶薪休養，直到至少 75% 後返工。詳見 [健康與恢復](employee-health.md)；人物卡及已開啟詳情同步顯示健康、效率與休養狀態。
